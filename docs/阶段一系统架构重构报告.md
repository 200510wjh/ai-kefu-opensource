# 阶段一系统架构重构报告

生成时间：2026-07-13

## 一、阶段目标

本阶段只做系统架构重构，不新增业务功能，不重新定义产品，不推倒重写现有系统。

产品定义保持为：AI 商家运营工作台，面向企业电商团队和数字化运营团队，核心能力沉淀在中间层，平台只作为 Connector 接入。

本阶段验收原则：

- 所有 AI 调用统一进入 AI Engine。
- 所有平台能力统一通过 Connector 描述和接入。
- 所有自动化能力统一通过 Workflow 描述和运行记录。
- 业务模块不直接面向具体平台扩展新逻辑。
- 保留现有可用能力，采用渐进式重构。

## 三、架构边界确认

### AI Engine 边界

以后回复、意向评分、风险识别、对话总结、脚本生成、商品文案、Prompt 生成、图片生成等 AI 能力，必须统一进入 AI Engine。

业务模块不能直接拼接第三方 AI API 地址，也不能直接读取前端传入的模型密钥。

### Workflow 边界

以后消息触发、线索触发、定时任务、人工触发，统一进入 Workflow。

本地脚本、平台自动化、客服自动回复、线索同步都应逐步变成 Workflow run，不再各自写一套运行状态。

### Connector 边界

以后抖音、微信、企业微信、淘宝、拼多多、闲鱼、官网和 API 都是 Connector。

业务模块只处理统一消息、统一线索、统一客户，不直接依赖某个平台页面结构或接口细节。

## 四、已知未完成与风险

### 1. MiniMax 图片生成仍有直连接口

当前 `backend/main.py` 中 MiniMax 图片生成仍然保留专用函数。

原因：这是已有媒体生成能力，直接迁移会影响商品媒体工厂。建议在第四阶段 AI Engine 深化时，把 MiniMax 做成 AI Engine 的图片 Provider Adapter。

影响：不影响客服和架构骨架，但图片生成还没有完全统一。

### 2. 前端页面导航尚未重构

当前前端仍是旧导航：

- 一页总控台
- 商品媒体工厂
- 客服脚本
- 渠道接入
- 知识库导入
- 会话收件箱
- 桌面自动客服
- 网页气泡

下一阶段必须改为固定导航：

- 企业管理
- 获客中心
- AI 客服
- CRM
- 知识库
- 商品中心
- 自动化中心
- AI 决策中心
- 经营分析
- 系统设置

页面允许显示“未启用”，但不能出现假按钮、假数据和无后端逻辑按钮。

### 3. 数据库尚未统一

当前只是新增统一业务模型骨架，还没有迁移数据库结构。

数据库统一认证、权限、日志、缓存、API 返回格式属于第三阶段。

### 4. 真实平台自动化未验收完成

微信、抖音、淘宝、拼多多、闲鱼、企业微信的真实桌面自动化，必须在真实登录窗口和真实消息场景里单独验收。

本阶段只建立 Connector 和 Workflow 架构，不声明真实平台全自动回复已经稳定商用。

### 5. 线上站点尚未部署本阶段改动

本阶段完成的是本地代码重构和本地构建验证。线上 `wjhai.cn` 是否更新，需要后续单独执行部署流程后再验收。
