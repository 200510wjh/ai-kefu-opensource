# 阶段六十：客户真实平台证据清单提交页报告

## 目标

阶段五十九已经让运营可以导入客户提供的真实脱敏证据链接。阶段六十把客户侧最后一步收口成一个公开签名页面：客户平台负责人可以一次性按六个验收场景填写脱敏截图、录屏、工单或平台审核页链接，系统生成导入预检和复核任务，但不自动登记 pass evidence。

## 新增能力

- 新增后台接口：`POST /api/v1/ops/platform-acceptance-evidence-manifest-link`
- 新增公开页面：`GET /api/v1/public/platform-acceptance-evidence-manifest`
- 新增公开提交接口：`POST /api/v1/public/platform-acceptance-evidence-manifest`
- 新增交付包文件：`Real-Platform-Customer-Evidence-Manifest-Link.md`
- 前端设置页新增 `Manifest link` 按钮和结果卡片。

## 客户提交内容

- `official_auth`：官方授权或开发者后台授权证明。
- `callback`：官方回调配置与验签证明。
- `read_message`：真实平台消息只读拉取证明。
- `read_lead`：真实平台线索只读拉取证明。
- `draft_reply`：真实客户消息生成待审核回复草稿证明。
- `customer_trial`：客户试运行材料。

## 安全边界

- 公开清单页只收脱敏 URL 和备注。
- 提交后只运行导入预检、生成回执和复核任务。
- 提交不会自动登记 pass evidence。
- 占位链接和疑似密钥内容会在导入预检阶段被阻塞。
- 运营仍必须在后台用 `CONFIRM_PLATFORM_EVIDENCE` 执行导入，最终门禁才可能变更。

## 当前结论

阶段六十把“客户提供真实证据链接”从口头/聊天交接变成可追踪表单。客户现在有一个集中页面可以一次性提交六项证据，运营随后使用导入预检和执行台完成最终验收收口。
