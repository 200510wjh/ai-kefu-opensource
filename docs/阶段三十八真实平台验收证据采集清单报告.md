# 阶段三十八：真实平台验收证据采集清单报告

## 阶段目标

在 Stage35-37 已经具备“登记证据、缺口转 CRM、通过证据后复验关闭”的基础上，补齐真实平台验收最后一公里：把剩余必需场景拆成可执行的证据采集清单，明确每个场景需要什么脱敏材料、如何采集、对应哪个 CRM 缺口任务。

## 本阶段新增

1. 后端新增 `PlatformAcceptanceEvidenceChecklistRequest`、`PlatformAcceptanceEvidenceChecklistItem`、`PlatformAcceptanceEvidenceChecklist`。
2. 新增接口：
   - `POST /api/v1/ops/platform-acceptance-evidence-checklist`
3. 清单覆盖真实平台必需场景：
   - `official_auth`
   - `callback`
   - `read_message`
   - `read_lead`
   - `draft_reply`
   - `customer_trial`
4. 每个清单项包含：
   - 当前状态：`passed` / `needs_evidence` / `needs_review`
   - 需要的脱敏证据
   - 采集步骤
   - 责任人、到期时间
   - 对应 CRM 任务 ID
   - 已有证据数量和最新证据引用
5. 前端设置页新增“证据清单”按钮和结果摘要。
6. 交付包新增 `真实平台验收证据采集清单.md`。
7. 验收矩阵和最终巡检新增对应 Stage38 项。

## 安全边界

- 本阶段不伪造平台证据。
- 本阶段不保存平台密码、token、cookie、验证码、签名密钥或 API secret。
- 生成清单可以补建缺口任务，但不会自动登记 pass 证据。
- 只有客户真实平台证据登记为 `pass` 后，才允许通过 Stage37 复验关闭对应缺口任务。

## 验证清单

1. `python -m py_compile backend/customer_service_saas.py backend/api_v1.py backend/main.py`
2. `npm run build`
3. `npm run secret-scan`
4. 使用 TestClient 登录演示商户。
5. 调用 `/api/v1/ops/platform-acceptance-evidence-checklist`。
6. 确认证据清单返回必需场景、缺失场景、CRM 任务映射和 artifact。
7. 生成交付包，确认包含 `真实平台验收证据采集清单.md`。
8. 运行最终验收巡检，确认出现“真实平台验收证据采集清单”项。
