# 阶段五十三：真实平台验收自动守护巡检报告

## 目标

阶段五十二已经把客户平台负责人的外部动作变成安全提交链接。阶段五十三新增自动守护巡检，把运营侧能做的复核同步、只读联调、缺口闭环、客户安全链接、负责人行动包和最终签署门禁复算串成一次执行，减少人工反复点击和漏项。

## 新增能力

- 新增后台接口：`POST /api/v1/ops/platform-acceptance-auto-watch-run`
- 新增前端入口：系统设置中的“自动守护”按钮。
- 新增交付包文件：`Real-Platform-Acceptance-Auto-Watch.md`

## 巡检顺序

1. 读取当前真实平台验收报告，记录闭环前缺口。
2. 同步客户材料复核任务。
3. 运行真实平台联调执行台，自动注册系统可验证的 pass evidence。
4. 运行剩余缺口闭环，按配置尝试 OAuth token exchange 和只读消息/线索拉取。
5. 如仍有缺口，生成客户平台负责人安全闭环链接。
6. 生成最新负责人行动包。
7. 复算最终签署门禁。
8. 写入下一次建议巡检时间。

## 安全边界

- 自动守护只执行只读检查、复核任务同步、客户链接生成和门禁复算。
- 不会发送客户消息，不会发布内容，不会修改客户平台数据。
- 不会自动审批客户提交的试运行材料。
- 只有已有可验证信号或人工审核通过的材料才能注册为 pass evidence。
- 最终签署仍以所有 required scenarios 具备可验证 pass evidence 为准。

## 当前结论

阶段五十三将真实平台验收推进到“自动守护等待外部证据”状态。系统侧已经能持续压缩运营动作，但最终通过仍取决于客户/官方平台提供授权、回调、只读样本、草稿记录和客户试运行脱敏材料。
