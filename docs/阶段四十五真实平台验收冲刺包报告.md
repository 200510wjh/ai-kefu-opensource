# 阶段四十五：真实平台验收冲刺包报告

## 阶段目标

把第40到44阶段形成的真实平台验收证据、缺口 CRM 任务、客户提交链接和材料复核流程聚合成一个可执行冲刺包。运营不再需要分别点证据清单、缺口任务和提交链接，而是可以在客户验收日前一键生成每个缺口场景的行动项。

## 本阶段新增

- 新增后端接口：`POST /api/v1/ops/platform-acceptance-sprint-pack`。
- 新增后端模型：`PlatformAcceptanceSprintPackRequest`、`PlatformAcceptanceSprintScenarioItem`、`PlatformAcceptanceSprintPack`。
- 冲刺包会复用真实平台验收清单，按未通过场景汇总：
  - 必需证据；
  - 采集步骤；
  - CRM 跟进任务；
  - 客户提交链接；
  - 下一步动作。
- 前端“平台接入配置向导”新增按钮：`验收冲刺包`。
- 前端展示最近冲刺包的缺失场景数、行动项数、CRM 任务数、客户链接数，并可打开 Markdown 报告和单场景提交页。
- 最终验收巡检和验收矩阵新增 `Platform acceptance sprint pack` 证据项，展示 `sprint_pack_events=`。

## 安全边界

- 冲刺包只推动真实材料采集，不自动登记 `pass` 证据。
- 客户提交链接只生成回执和复核任务，不关闭真实平台验收缺口。
- 只有运营人工审核脱敏材料并显式登记通过证据后，缺口复验才可以关闭对应 CRM 任务。
- 文档和报告不写入服务器密码、平台 token、cookie、验证码、原始签名密钥或 API secret。

## 验收口径

- 生成冲刺包后，artifact 标题应包含 `Real Platform Acceptance Sprint Pack`。
- 冲刺包中未通过场景应继续显示为待采集或待复核状态。
- 最终巡检应出现 `sprint_pack_events=`。
- 如果仍缺少客户官方授权、回调、消息读取、线索读取、回复草稿和客户试运行证据，系统状态仍应保持 `ready_with_boundaries`，不能声明真实平台验收完全完成。
