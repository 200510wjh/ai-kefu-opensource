# 阶段五十九：真实平台证据导入与门禁预检报告

## 目标

阶段五十八已经具备从复核处理台到审核执行台的确认链路。阶段五十九补齐真实证据导入收口：运营拿到客户脱敏截图、录屏、工单或平台审核页链接后，可以一次性提交 JSON 清单，先预检 6 个必需场景是否齐全，再在确认后登记 pass evidence 并复验门禁。

## 新增能力

- 新增后端接口：`POST /api/v1/ops/platform-acceptance-evidence-import`
- 新增导入请求模型：`PlatformAcceptanceEvidenceImportRunRequest`
- 新增导入结果模型：`PlatformAcceptanceEvidenceImportRun`
- 前端设置页新增 `Import preview` 和 `Import evidence` 按钮。
- 交付包新增 `Real-Platform-Evidence-Import-Preview.md`。

## 导入规则

- 预览模式只校验，不登记证据。
- 执行模式必须输入 `CONFIRM_PLATFORM_EVIDENCE`。
- 每个通过场景必须提供脱敏、客户可控、非占位的证据链接。
- `example.com`、`localhost`、`127.0.0.1`、`.invalid` 等占位链接会被阻塞。
- 导入执行仍复用审核决策链路，保留敏感信息扫描、复核任务关闭和缺口复验门禁。

## JSON 清单格式

```json
[
  {
    "scenario": "official_auth",
    "connector": "website",
    "account_label": "customer platform account",
    "operator": "operations reviewer",
    "evidence_note": "Sanitized proof summary.",
    "evidence_url": "https://customer-controlled.example/path",
    "review_task_ids": []
  }
]
```

## 安全边界

- 导入预检不是通过证据。
- 系统不会从空白项、占位链接或疑似包含密钥的文本生成 pass evidence。
- 生产环境必须等客户提供真实脱敏材料后才能执行导入。
- 最终签署门禁继续只认真实 pass evidence。

## 当前结论

阶段五十九把最后的真实证据收口做成可操作导入流程。现在运营不需要逐条手工登记，只要客户提供 6 个真实脱敏证据链接，就可以先预检、再确认导入、再复验最终门禁。
