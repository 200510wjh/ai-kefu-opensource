# 阶段四十九：真实平台剩余缺口闭环指挥台报告

生成时间：2026-07-17

## 本阶段目标

第 48 阶段上线后，线上真实验收缺口从 6 个收敛到 4 个：`official_auth`、`read_message`、`read_lead`、`customer_trial`。第 49 阶段新增“剩余缺口闭环指挥台”，把这些缺口从静态清单变成可执行闭环动作。

## 已实现内容

新增后端接口：

- `POST /api/v1/ops/platform-acceptance-gap-closure-run`

新增交付产物：

- `Real Platform Remaining Gap Closure Run`
- 交付包文件：`Real-Platform-Remaining-Gap-Closure-Run.md`

新增前端入口：

- 系统设置中的“缺口闭环”按钮。
- 可选择是否尝试 OAuth token exchange。
- 可选择是否执行只读消息/线索拉取。
- 可生成客户试运行材料提交链接。
- 展示闭环前缺口、闭环后缺口、每项缺字段、下一步动作、CRM 任务和最终签署门禁状态。

## 闭环策略

- `official_auth`：如果已有 OAuth code 且 token exchange 必需字段齐全，系统可尝试换取访问凭证；成功后登记脱敏 pass 证据。
- `read_message`：如果已有访问凭证和消息只读 endpoint，系统可执行只读拉取；有真实样本后登记 pass 证据。
- `read_lead`：如果已有访问凭证和线索只读 endpoint，系统可执行只读拉取；有真实样本后登记 pass 证据。
- `customer_trial`：系统只生成客户提交链接和复核任务，不自动登记 pass。

## 安全边界

- 闭环指挥台不伪造证据。
- 交付包生成时不会主动 token exchange 或拉取客户平台，只做预览和链接生成。
- 只读拉取不会发送消息。
- 客户试运行材料必须由客户提交，运营复核后才能登记 pass。
- 最终签署仍由门禁控制，只有 live run `ready_for_signoff` 时才释放签署链接。

## 当前状态

系统闭环能力已完成。真正进入最终签署还需要：

1. 补齐 official auth 所需的 token endpoint / app 参数并完成 token exchange。
2. 配置消息只读 endpoint 并产生可拉取样本。
3. 配置线索只读 endpoint 并产生可拉取样本。
4. 客户提交试运行材料，运营审核后登记 `customer_trial` pass 证据。
