# 阶段六十七：恢复包负责人复核闭环报告

## 目标

阶段六十六已经把旧 Manifest 提交恢复为可预览的复核包，但恢复包仍缺少负责人决策闭环。阶段六十七补齐队列级复核动作，让运营可以对 `recovered_for_review` 记录明确结论，并在需要时生成新的客户 Manifest 链接。

## 已完成

- 新增 `POST /api/v1/ops/platform-acceptance-manifest-recovery-review`。
- 支持恢复包复核预览：`execute=false` 不写入复核审计。
- 支持执行复核：`accepted_for_preview`、`needs_customer_resubmission`、`rejected`。
- `needs_customer_resubmission` 可生成新的客户 Manifest 链接，让客户重新提交结构化脱敏证据。
- Manifest import queue 项新增最近一次恢复复核状态：
  - `recovery_review_id`
  - `recovery_review_status`
  - `recovery_review_decision`
- 前端 Import queue 新增恢复包复核按钮：
  - `Review preview`
  - `Mark reviewed`
  - `Request resubmission`
- 前端新增 Recovery review 结果条，可打开重提 Manifest 或复核报告。

## 安全边界

- 恢复包复核不会注册 pass evidence。
- `execute=false` 仅预览，不写复核审计。
- `execute=true` 只记录复核结论和可选客户 Manifest 链接。
- 客户 Manifest 链接只收集结构化脱敏证据，不自动批准材料。
- 最终 pass evidence 仍必须通过原始导入门禁：真实材料、URL 安全预检、人工确认和 `CONFIRM_PLATFORM_EVIDENCE`。
