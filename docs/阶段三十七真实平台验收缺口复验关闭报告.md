# 阶段三十七：真实平台验收缺口复验关闭报告

## 目标

在 Stage36 把真实平台验收缺口同步为 CRM 任务之后，补齐“有 pass 脱敏证据后自动关闭对应缺口任务”的复验闭环。

## 已完成

1. 后端新增复验模型
   - `PlatformAcceptanceGapReconcileRequest`
   - `PlatformAcceptanceGapReconcileResult`

2. 后端新增接口
   - `POST /api/v1/ops/platform-acceptance-gap-reconcile`
   - 权限：`settings:write`
   - 输出：已通过证据场景、关闭任务数、仍打开任务数、关闭任务列表、仍打开任务列表、Markdown artifact。

3. 关闭逻辑
   - 只处理 `source=platform_acceptance_gap` 且 `status=open` 的 CRM 任务。
   - 任务 target_id 必须为 `platform_acceptance:{scenario}`。
   - 只有该 `scenario` 已登记 `result=pass` 的真实平台验收脱敏证据时，才关闭对应任务。

4. 前端设置页接入
   - 新增“复验缺口”按钮。
   - 展示已通过场景、已关闭任务数、仍打开任务数和复验报告 artifact。

5. 交付包和验收纳入
   - 交付包新增 `真实平台验收缺口复验关闭报告.md`。
   - 验收矩阵新增 `Platform acceptance gap reconcile`。
   - 最终验收巡检新增“真实平台验收缺口复验关闭”。

## 安全边界

- 本阶段只根据已登记的 pass 脱敏证据关闭 CRM 任务，不伪造证据。
- 不保存平台密码、token、cookie、验证码或密钥。
- 真实完成仍以客户账号、官方授权、真实消息/线索和脱敏证据为准。
