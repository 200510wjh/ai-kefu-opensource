# 阶段二十一：回复外发准备、撤回与审计报告

生成时间：2026-07-16

## 本阶段目标

在回复草稿人工确认队列之后，补齐“外发前”的安全闭环：已审批回复可以进入外发准备队列，运营人员可复制到官方后台人工发送，也可以在发送前撤回准备记录。系统继续保持不自动外发平台消息。

## 已完成内容

- 新增数据表：
  - `reply_dispatches`
- 新增后端模型：
  - `ReplyDispatchCreateRequest`
  - `ReplyDispatchRevokeRequest`
  - `ReplyDispatchItem`
- 新增 v1 API：
  - `GET /api/v1/reply-dispatches`
  - `POST /api/v1/reply-drafts/{draft_id}/dispatch`
  - `POST /api/v1/reply-dispatches/{dispatch_id}/revoke`
- 后端安全策略：
  - 只有 `approved` 草稿可以进入外发准备队列
  - 当前默认 `manual_copy`
  - 即使请求 `api_send`，只要 Connector 未开启 `send_enabled`，也会降级为 `manual_copy`
  - 进入 outbox 时保存回复快照、风险标记、操作人和备注
  - 撤回时记录 `revoked_at` 和撤回备注
  - 创建和撤回均写入审计日志
- 前端 AI 客服页新增：
  - “通过并准备发送”按钮
  - 外发准备队列
  - 复制外发文案
  - 撤回外发准备记录
- 最终验收巡检新增“回复外发准备和撤回审计”。
- 交付包验收矩阵新增“回复外发准备和撤回审计”。

## 安全边界

- 本阶段不自动发送微信、抖音、淘宝、拼多多、闲鱼消息。
- 外发准备队列只是人工发送前的操作记录和复制入口。
- 撤回只撤回系统内的准备记录；如果运营人员已经在官方后台手动发出，需要到官方后台处理真实撤回。
- 真实 API 自动发送必须另行完成官方权限、验签、频控、撤回能力和风控策略后再开启。

## 验收方式

1. 创建回复草稿。
2. 未审批时调用 dispatch，应被拒绝。
3. 审批草稿为 `approved`。
4. 调用 dispatch，确认生成 `manual_ready` 记录。
5. 调用 revoke，确认状态变为 `revoked`。
6. 检查审计日志出现创建和撤回记录。
