# 阶段四十二：审核通过联动缺口复验报告

## 阶段目标

Stage41 已经能在审核通过后登记真实平台验收 `pass` 证据。本阶段补齐最后一步联动：审核通过并登记证据后，可以自动运行真实平台验收缺口复验，关闭与该 `pass` 证据匹配的 CRM 缺口任务。

## 本阶段新增

1. `PlatformAcceptanceEvidenceReviewDecisionRequest` 新增：
   - `reconcile_gap_tasks`
2. `PlatformAcceptanceEvidenceReviewDecision` 新增：
   - `gap_reconcile`
3. 审核决策 artifact 新增 Gap Reconciliation 区块。
4. 前端审核决策流程新增“是否联动复验并关闭匹配缺口”确认。
5. 最终巡检新增“审核通过联动缺口复验”。

## 行为规则

- 只有 `decision=approved` 且 `register_pass_evidence=true` 时，才允许联动复验。
- 联动复验仍需要确认短语 `CONFIRM_PLATFORM_EVIDENCE`。
- 联动复验复用 Stage37 逻辑，只关闭已经有 `pass` 证据的匹配缺口任务。
- 未登记 `pass` 证据时，不能触发缺口复验。

## 安全边界

- 本阶段不伪造真实平台证据。
- 审核材料仍需人工确认脱敏。
- 复验只依据已经登记的 `pass` 证据，不依据回执、通知或未审核材料。

## 验证清单

1. `python -m py_compile backend/customer_service_saas.py backend/api_v1.py backend/main.py`
2. `npm run build`
3. `npm run secret-scan`
4. 使用非必需 `ops_health` 创建临时缺口任务、submitted 回执和复核任务。
5. 审核通过时登记 `ops_health` pass 证据并开启 `reconcile_gap_tasks`。
6. 确认只关闭 `ops_health` 临时缺口，不影响 5 个必需真实平台缺口。
7. 运行最终验收巡检，确认出现 Stage42 项。
