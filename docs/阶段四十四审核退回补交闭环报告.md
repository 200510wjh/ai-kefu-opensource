# 阶段四十四：审核退回补交闭环报告

## 目标

当真实平台验收材料审核结果为 `needs_redaction` 或 `rejected` 时，运营可以直接生成同场景的客户补交链接，让客户重新提交脱敏材料，并再次进入回执与复核任务。

## 后端

`PlatformAcceptanceEvidenceReviewDecisionRequest` 新增：

- `request_resubmission_link`

`PlatformAcceptanceEvidenceReviewDecision` 新增：

- `resubmission_link`

行为规则：

1. `approved` 决策不允许生成补交链接。
2. `needs_redaction` / `rejected` 可生成补交链接。
3. 补交链接使用第 43 阶段签名 token 机制。
4. 补交链接只收集脱敏材料，不登记 pass 证据。
5. 最终验收巡检新增“审核退回补交闭环”。

## 前端

审核决策弹窗新增：

- 退回或需脱敏时询问是否生成客户补交材料链接。
- 生成后自动复制链接。
- 审核结果区展示补交链接数量，并可打开补交页。

## 验收

本地和线上验收使用非必需 `ops_health` 场景：

1. 创建 `needs_redaction` 审核决策。
2. 启用 `request_resubmission_link`。
3. 确认决策返回 `resubmission_link`。
4. 打开补交链接页面。
5. 用补交链接提交脱敏材料。
6. 确认生成新回执和复核任务。
7. 确认最终巡检证据包含 `review_resubmission_links=`。

## 边界

补交链接只是客户材料收集入口，不能替代运营审核；只有运营显式审核通过并输入确认短语后，系统才会登记 pass 证据并触发缺口复验。
