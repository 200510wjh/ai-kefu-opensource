# 阶段五十八：真实平台审核执行台报告

## 目标

阶段五十七已经把客户回执后的复核状态整理成处理台。阶段五十八继续补齐“从待审核到登记证据”的执行面：运营可以先预览待执行清单，再在人工确认脱敏材料后批量登记 pass evidence、关闭复核任务并触发缺口复验。

## 新增能力

- 新增后端接口：`POST /api/v1/ops/platform-acceptance-review-execution`
- 新增执行请求模型：`PlatformAcceptanceReviewExecutionRunRequest`
- 新增执行结果模型：`PlatformAcceptanceReviewExecutionRun`
- 前端设置页新增 `Execution preview` 和 `Execute review` 按钮。
- 交付包新增 `Real-Platform-Acceptance-Review-Execution-Preview.md`。

## 执行模式

- `execute=false`：只生成预览 artifact，不登记证据、不关闭任务、不复验缺口。
- `execute=true`：必须输入 `CONFIRM_PLATFORM_EVIDENCE`，并且 approved 项必须有脱敏证据链接。
- 每条执行仍复用既有审核决策接口，因此继续受敏感信息扫描、确认短语、证据登记、缺口复验门禁约束。

## 安全边界

- 执行台不会伪造真实平台证据。
- 没有脱敏证据链接的 approved 项会被阻塞。
- 客户回执、执行预览、复核任务都不能替代 pass evidence。
- 生产环境没有真实客户材料时，只能使用预览模式验证接口可用性。

## 当前结论

阶段五十八把“待审核材料”推进成可执行清单：运营可以批量预览，确认后批量走已有审核决策链路登记证据与复验缺口。最终签署门禁仍只认真实 pass evidence，不会因预览或回执自动放开。
