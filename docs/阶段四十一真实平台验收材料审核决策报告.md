# 阶段四十一：真实平台验收材料审核决策报告

## 阶段目标

Stage40 已经能把客户提交的真实平台验收材料转成 CRM 复核任务。本阶段补齐“审核结果怎么进入证据闭环”：运营可以记录审核决策，必要时登记为 `pass` 证据，并关闭对应复核任务。

## 本阶段新增

1. 后端新增：
   - `PlatformAcceptanceEvidenceReviewDecisionRequest`
   - `PlatformAcceptanceEvidenceReviewDecision`
2. 新增接口：
   - `POST /api/v1/ops/platform-acceptance-evidence-review-decision`
3. 前端设置页新增“审核决策”按钮。
4. 交付包新增 `真实平台验收材料审核决策模板.md`。
5. 验收矩阵和最终巡检新增“真实平台验收材料审核决策”。

## 行为规则

- `needs_redaction`：只记录决策，不登记证据，不关闭缺口。
- `rejected`：只记录驳回，不登记证据，不关闭缺口。
- `approved`：只有显式传入 `register_pass_evidence=true` 且确认短语为 `CONFIRM_PLATFORM_EVIDENCE`，才会登记 `pass` 证据。
- 关闭复核任务也需要同一个确认短语。
- 登记 `pass` 后仍需 Stage37 复验关闭对应真实平台验收缺口。

## 安全边界

- 审核决策不会绕过证据安全扫描。
- 禁止保存密码、token、cookie、验证码、签名密钥或 API secret。
- 测试阶段只允许使用非必需场景或脱敏样例，不能伪造必需真实平台证据。

## 验证清单

1. `python -m py_compile backend/customer_service_saas.py backend/api_v1.py backend/main.py`
2. `npm run build`
3. `npm run secret-scan`
4. 使用非必需 `ops_health` 场景创建 submitted 回执和复核任务。
5. 调用 `/api/v1/ops/platform-acceptance-evidence-review-decision` 记录 `needs_redaction` 决策。
6. 调用同一接口在确认短语下为 `ops_health` 登记 `pass` 证据并关闭复核任务。
7. 确认 artifact 明确写明审核边界。
8. 生成交付包，确认包含 `真实平台验收材料审核决策模板.md`。
9. 运行最终验收巡检，确认出现 Stage41 项。
