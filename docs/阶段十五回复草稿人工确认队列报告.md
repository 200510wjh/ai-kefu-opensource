# 阶段十五：回复草稿人工确认队列报告

生成时间：2026-07-16 20:47:30

## 本阶段目标

补齐 Connector 接入后的“平台消息草稿和人工确认队列”，让系统在不越过官方授权边界的前提下，把只读入站消息转成可审核、可复制、可追踪的回复草稿。

## 已完成内容

- 新增回复草稿队列表：`reply_drafts`。
- 新增后端模型：
  - `ReplyDraftQueueCreateRequest`
  - `ReplyDraftReviewRequest`
  - `ReplyDraftQueueItem`
- 新增 v1 API：
  - `GET /api/v1/reply-drafts`
  - `POST /api/v1/reply-drafts`
  - `PATCH /api/v1/reply-drafts/{draft_id}/review`
- Connector 消息只读入站后，如果该 Connector 支持 `draft_reply`，自动生成 `pending` 回复草稿。
- 手动回复草稿可以加入人工确认队列。
- 草稿支持通过、驳回和复制。
- 生成和审核都会写入审计日志。
- 生成草稿会写入 `reply_draft` 用量记录。
- 最终验收巡检新增“回复草稿人工确认队列”验收项。

## 安全边界

- 当前只生成回复草稿，不自动发送平台消息。
- 审核通过代表“可复制后人工发送”，不代表系统已经取得平台官方发送权限。
- 涉及价格、退款、投诉、账号、隐私、付款等风险消息仍必须人工确认。

## 本地验证

- Python 编译通过。
- 前端构建通过。
- TestClient 冒烟通过：
  - `POST /api/v1/reply-drafts` 手动创建草稿。
  - `GET /api/v1/reply-drafts?status=pending` 查询待确认草稿。
  - `PATCH /api/v1/reply-drafts/{id}/review` 审核通过。
  - `POST /api/v1/connectors/douyin_dm/messages/read` 只读入站后自动生成 `draft_id`。
  - `POST /api/v1/acceptance/audit` 出现草稿队列验收项。

## 交付说明

客户试运行时，客服主管每天进入 AI 客服页查看“人工确认队列”，逐条复核草稿并复制到对应平台人工发送。正式切换自动发送前，仍需官方 API 权限、验签、审计、人审策略和灰度开关。
