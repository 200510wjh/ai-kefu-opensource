# 阶段五十六：客户验收房间回执与责任锁定报告

## 目标

阶段五十五已经把客户侧入口集中到一个验收房间。阶段五十六继续推进到“客户可回执、系统可落证据、运营可追责”：客户平台负责人在房间内确认已收到、已提交材料或需要协助后，系统立即生成脱敏回执记录，并在需要时同步复核任务。

## 新增能力

- 新增公开回执接口：`POST /api/v1/public/platform-acceptance-customer-room-receipt`
- 扩展公开验收房间：`GET /api/v1/public/platform-acceptance-customer-room`
- 新增业务记录：`PlatformAcceptanceCustomerRoomReceipt`
- 新增交付产物：`/artifacts/integration/platform-customer-room-receipt-*.md`
- 房间报告新增 `Room receipt` 行，客户打开房间即可完成回执。

## 回执状态

- `acknowledged`：客户确认已收到验收房间，不自动关闭任何缺口。
- `submitted`：客户表示已提交材料，系统记录回执并同步复核任务。
- `needs_help`：客户表示需要协助，系统记录回执并同步复核任务。

## 安全边界

- 回执必须勾选“无敏感信息”确认。
- 回执文本和材料链接会复用现有敏感字段扫描，阻止密码、token、cookie、验证码、签名密钥、API secret 等内容入库。
- 回执不是通过证据；运营仍需审核脱敏材料，并通过证据登记接口注册可验证的 pass evidence。
- 最终签署仍受真实平台证据门禁控制，未补齐官方授权、回调、读消息、读线索、草稿回复、客户试用前不会开放。

## 当前结论

阶段五十六把验收房间从“只读入口聚合”推进为“可提交回执的责任闭环”。客户平台负责人可以在同一页面告知当前进度，系统会生成可追踪 artifact，并把需要运营处理的回执变成复核任务。
