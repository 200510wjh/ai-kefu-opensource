# 阶段六十九：客户重提追踪催办看板报告

## 目标

阶段六十八已经把恢复包批量转换为客户 Manifest 重提链路。阶段六十九新增重提追踪看板，持续判断客户是否已提交、是否已可复核、是否需要催办或重新生成链路。

## 已完成

- 新增 `POST /api/v1/ops/platform-acceptance-manifest-resubmission-tracker`。
- Manifest link 审计新增场景、接收人、到期时间和 artifact 信息。
- Manifest submission 审计新增 `link_id`，便于后续精确关联客户提交。
- Tracker 支持状态：
  - `waiting_customer`
  - `ready_for_review`
  - `needs_fix`
  - `stale`
  - `complete`
  - `missing_link`
- Tracker 生成可复制的客户催办草稿。
- 前端新增 `Resubmit tracker` 按钮和结果面板，展示等待、待复核、超时、最新提交和预览 artifact。

## 安全边界

- Tracker 是只读看板，不发送消息、不批准证据、不注册 pass evidence。
- 客户提交后只进入 `ready_for_review`，仍需人工审核、URL 预检和 `CONFIRM_PLATFORM_EVIDENCE`。
- 催办草稿必须人工确认后再发送。
- Tracker 只展示 artifact 链接，不在审计中新增明文签名 Manifest URL。
