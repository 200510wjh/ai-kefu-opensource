# 阶段二十七：平台接入干跑验收报告

## 目标

在真实平台官方授权、访问凭证和 endpoint 尚未全部到位时，系统也能自动检查接入前置条件，明确哪些 Connector 可以进入联调，哪些仍因缺少官方资料而失败。

## 已完成能力

1. 新增后端干跑验收模型：
   - `IntegrationDryRunRequest`
   - `IntegrationDryRunCheck`
   - `IntegrationDryRun`

2. 新增后端接口：
   - `POST /api/v1/ops/integration-dry-run`
   - 支持按 Connector 过滤。
   - 支持生成 Markdown artifact。

3. 干跑检查范围：
   - OAuth app 字段是否齐全。
   - OAuth code、access token/session key、refresh token 是否具备。
   - 官方只读 API 是否同时具备访问凭证和 endpoint。
   - Webhook 签名材料是否配置。
   - 受控发送是否保持人工确认边界。
   - Connector 运维健康是否存在 fail/warning。

4. 前端系统设置页接入：
   - “平台接入配置向导”面板新增“干跑验收”按钮。
   - 运行后打开 Markdown 报告。
   - 页面显示最近干跑检查数量和状态。

5. 交付包与验收接入：
   - 客户交付包自动包含 `平台接入干跑验收.md`。
   - 验收矩阵新增 `Platform integration dry run`。
   - 最终验收巡检新增“平台接入干跑验收”。

## 安全边界

- 干跑验收不调用真实平台 endpoint。
- 干跑验收不发送消息、不发布商品、不改价、不退款、不发货。
- fail/warning 代表仍需官方授权、凭证或 endpoint，不代表系统伪造完成。

## 验证清单

1. Python 编译通过。
2. 前端 `npm run build` 通过。
3. TestClient 能运行干跑验收并生成 artifact。
4. 交付包包含 `平台接入干跑验收.md`。
5. 最终验收巡检包含 dry run 证据。
6. secret scan 通过后部署。
