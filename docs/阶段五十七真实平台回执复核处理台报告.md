# 阶段五十七：真实平台回执复核处理台报告

## 目标

阶段五十六让客户可以在验收房间内提交回执。阶段五十七把运营侧的后续动作整理成复核处理台：系统按六个必需验收场景汇总当前证据、客户回执、复核任务和下一步动作，减少运营在多个按钮和弹窗之间来回判断。

## 新增能力

- 新增后端接口：`POST /api/v1/ops/platform-acceptance-review-desk`
- 新增业务模型：`PlatformAcceptanceReviewDesk`
- 新增场景行模型：`PlatformAcceptanceReviewDeskScenario`
- 前端设置页新增 `Review desk` 按钮和结果卡片。
- 交付包新增 `Real-Platform-Acceptance-Review-Desk.md`。

## 处理台状态

- `passed`：该场景已有可验证 pass evidence。
- `ready_to_review`：客户已经提交材料，运营需要人工审核。
- `needs_customer_help`：客户表示需要协助，运营需要联系客户补充材料。
- `needs_evidence`：还没有可复核材料，继续通过客户验收房间或材料提交链接收集证据。

## 安全边界

- 处理台不会自动登记 pass 证据。
- 处理台不会自动关闭真实平台验收缺口。
- 审核通过、证据登记、缺口复验仍必须走既有审核决策接口和 `CONFIRM_PLATFORM_EVIDENCE` 确认短语。
- 只有脱敏、可验证、客户可控的真实平台材料才能进入 pass evidence。

## 当前结论

阶段五十七把“客户已回执”之后的运营工作从零散动作整理成一个可视化处理台。系统现在能明确告诉运营：哪些场景已经通过、哪些可以审核、哪些需要客户协助、哪些还缺真实平台证据。
