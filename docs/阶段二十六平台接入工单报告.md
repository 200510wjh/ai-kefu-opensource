# 阶段二十六：平台接入工单报告

## 目标

第 25 阶段已经把 Connector 缺口整理成配置向导。本阶段继续向前，把这些缺口自动生成客户可执行的“平台接入工单”，让客户平台管理员或技术负责人知道要准备哪些官方资料、填哪些字段、如何验收。

## 已完成能力

1. 新增后端工单模型：
   - `IntegrationWorkOrderRequest`
   - `IntegrationWorkOrderItem`
   - `IntegrationWorkOrder`

2. 新增后端接口：
   - `POST /api/v1/ops/integration-work-order`
   - 默认从 `/api/v1/ops/setup-guide` 推导未完成任务。
   - 支持按 Connector 过滤，也支持 `include_done=true` 导出全量留档。

3. 新增工单 Markdown artifact：
   - 生成目录：`/artifacts/integration/`
   - 内容包括 Connector、类别、优先级、负责人、需要字段、已配置字段、下一步、验收动作。
   - 工单只列字段名，不导出真实密钥值。

4. 前端系统设置页接入：
   - “平台接入配置向导”面板新增“生成工单”按钮。
   - 生成后自动打开 Markdown 工单。
   - 页面显示最近工单任务数和打开入口。

5. 交付包与验收接入：
   - 客户交付包自动包含 `平台接入工单.md`。
   - 验收矩阵新增 `Platform integration work order`。
   - 最终验收巡检新增“平台接入工单”。

## 安全边界

- 工单不包含 client secret、app secret、access token、session key、refresh token 等真实敏感值。
- 敏感值只能在后台密码框录入，由后端加密保存。
- 自动发送仍需要人工确认、低风险校验、频控和审计。
- 未获得官方授权前，不声明平台自动收发已经完成。

## 验证清单

1. Python 编译通过。
2. 前端 `npm run build` 通过。
3. TestClient 能生成平台接入工单 artifact。
4. 交付包包含 `平台接入工单.md`。
5. 最终验收巡检包含工单证据。
6. secret scan 通过后部署。
