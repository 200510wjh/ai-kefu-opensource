# 阶段三后端重构报告

生成时间：2026-07-16

## 一、阶段目标

本阶段目标是完成后端基础架构重构，重点是统一认证、权限、日志、异常处理、缓存和 API 返回格式。

根据阶段二报告中的架构冲突，本阶段采用兼容式重构：

- 保留旧 `/api/*` 接口返回格式，避免破坏现有前端、验收脚本和线上调用。
- 新增 `/api/v1/*` 接口，统一使用标准返回格式。
- 新增的后端能力以后优先走 `/api/v1/*`。

## 二、本阶段新增文件

### 1. `backend/platform/api.py`

新增统一 API 响应和请求上下文：

- `ApiResponse`
- `ApiError`
- `success_response`
- `error_response`
- `request_context_middleware`
- `http_exception_handler`
- `unhandled_exception_handler`

统一返回格式：

```json
{
  "ok": true,
  "data": {},
  "error": null,
  "request_id": "uuid",
  "elapsed_ms": null
}
```

错误返回格式：

```json
{
  "ok": false,
  "data": null,
  "error": {
    "code": "HTTP_ERROR",
    "message": "错误信息",
    "details": {}
  },
  "request_id": "uuid",
  "elapsed_ms": null
}
```

### 2. `backend/platform/cache.py`

新增轻量运行时缓存：

- `TTLCache`
- `runtime_cache`

当前用于 Connector 状态短缓存，后续可以用于低频配置、平台状态、AI Engine 状态等。

### 3. `backend/platform/security.py`

新增统一认证和权限上下文：

- `AuthContext`
- `require_auth`
- `require_permission`
- `optional_bearer_token`

当前复用已有 `current_merchant`，不重复造登录系统。

### 4. `backend/api_v1.py`

新增 `/api/v1` 路由层，所有返回统一包。

当前已接入：

- `GET /api/v1/health`
- `POST /api/v1/auth/login`
- `GET /api/v1/enterprise/profile`
- `PUT /api/v1/enterprise/profile`
- `GET /api/v1/enterprise/dashboard`
- `GET /api/v1/crm/conversations`
- `GET /api/v1/crm/conversations/{session_id}`
- `POST /api/v1/crm/conversations/{session_id}/handoff`
- `GET /api/v1/knowledge/items`
- `POST /api/v1/knowledge/import`
- `GET /api/v1/settings/channels`
- `PUT /api/v1/settings/channels/{channel}`
- `GET /api/v1/connectors`
- `GET /api/v1/workflows/runs`
- `GET /api/v1/ai-engine/status`

## 四、架构边界确认

### 认证

当前认证继续复用已有商户登录和 Bearer token。

新的 `/api/v1` 通过 `AuthContext` 承接用户、企业和权限，后续可扩展：

- 企业成员
- 角色
- 权限点
- 团队空间
- 审计日志

### 权限

已建立权限依赖骨架：

- `enterprise:read`
- `enterprise:write`
- `crm:read`
- `knowledge:write`
- `automation:run`
- `settings:write`

当前默认 owner 拥有全部权限。后续企业成员表接入后，可以替换为数据库权限。

### 统一 API

以后新增接口优先使用 `/api/v1/*` 和统一返回格式。

旧 `/api/*` 只做兼容保留，不继续扩展新业务能力。

### 日志与异常

所有请求会写入：

- `X-Request-ID`
- `X-Response-Time-Ms`

`/api/v1` 异常会返回统一错误格式。

旧接口错误格式保持 FastAPI 原格式，避免破坏兼容。

### 缓存

当前仅做内存 TTLCache。

后续如果部署多进程或多机器，需要替换为 Redis 缓存。
