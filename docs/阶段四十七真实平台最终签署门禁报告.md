# 阶段四十七：真实平台最终签署门禁报告

生成时间：2026-07-17

## 本阶段目标

第 46 阶段已经有真实平台验收作战台和客户最终签署草稿，但还缺少一个硬门禁：在官方授权、回调、消息读取、线索读取、回复草稿、客户试运行等真实平台场景没有全部通过前，系统不能给客户开放最终签署链接。

第 47 阶段补齐“最终签署门禁”：

- 运营可生成最终签署门禁报告。
- 门禁会复用真实平台验收作战台结果。
- 只有 live run 状态为 `ready_for_signoff` 时，才返回公开签署页链接。
- 当前仍有缺口时，报告为 `blocked`，不返回可发送签署链接。
- 公开签署提交会再次重算 live run 状态，防止旧链接绕过当前证据门槛。

## 已实现内容

后端新增：

- `POST /api/v1/ops/platform-acceptance-final-signoff-link`
- `GET /api/v1/public/platform-acceptance-final-signoff`
- `POST /api/v1/public/platform-acceptance-final-signoff`

核心产物：

- `Real Platform Acceptance Final Sign-off Gate`
- `Real Platform Acceptance Final Sign-off`
- 交付包文件：`Real-Platform-Acceptance-Final-Signoff-Gate.md`

前端新增：

- 系统设置里的“签署门禁”按钮。
- 门禁状态、缺口场景数、签署人、到期时间展示。
- 门禁报告打开入口。
- 仅在后端返回 `ready` 且存在 `submit_url` 时，才显示/复制最终签署页链接。

## 安全边界

- 不保存平台密码、token、cookie、验证码、签名密钥或 API secret。
- 最终签署只保存脱敏确认信息和验收状态。
- 客户点击公开签署页后，后端仍会重新生成 live run 并检查是否 `ready_for_signoff`。
- 如果真实平台证据仍缺失，即使拿到旧链接，也无法提交 `accepted`。

## 当前状态

当前真实平台验收仍未完成最终客户签署条件：

- 缺少官方授权真实通过证据。
- 缺少官方回调真实通过证据。
- 缺少消息读取真实通过证据。
- 缺少线索读取真实通过证据。
- 缺少回复草稿真实通过证据。
- 缺少客户试运行真实通过证据。

因此本阶段状态是：门禁能力已完成，但最终验收仍处于 `blocked / collecting` 边界内，不能对客户声明真实平台最终验收已签署完成。

## 下一阶段建议

第 48 阶段应进入真实客户平台联调收口：

1. 用客户官方账号补齐 OAuth 授权和回调证据。
2. 拉取一轮真实消息和线索。
3. 生成一条真实回复草稿，但仍保持人工确认。
4. 让客户完成试运行材料提交。
5. 审核通过后重新运行验收作战台。
6. 仅当 live run 变为 `ready_for_signoff` 后，再生成最终签署链接。
