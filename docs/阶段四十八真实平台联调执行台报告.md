# 阶段四十八：真实平台联调执行台报告

生成时间：2026-07-17

## 本阶段目标

第 47 阶段已经建立最终签署门禁，但真实平台验收仍缺少 6 个客户平台证据场景。第 48 阶段补齐“联调执行台”，让运营在客户完成官方授权和只读 API 配置后，可以一键执行真实平台联调，并把系统可证明的结果自动沉淀为脱敏验收证据。

## 已实现内容

新增后端接口：

- `POST /api/v1/ops/platform-acceptance-joint-debug-run`

新增交付产物：

- `Real Platform Joint Debug Run`
- 交付包文件：`Real-Platform-Joint-Debug-Run.md`

新增前端入口：

- 系统设置中的“联调执行台”按钮。
- 可输入指定 connector，也可留空使用已配置 connector。
- 可选择是否立即执行只读官方 API 拉取。
- 展示通过数、缺口数、connector 数、场景状态、拉取结果、证据入口和下一步。

## 自动补证规则

联调执行台只在有可核验信号时登记 pass 证据：

- `official_auth`：已密文保存 `access_token` 或 `session_key`。
- `callback`：已有 OAuth callback 审计记录或 `oauth_code` 字段。
- `read_message`：只读消息 API 拉取成功，且有导入或重复样本。
- `read_lead`：只读线索 API 拉取成功，且有导入或重复样本。
- `draft_reply`：已存在对应 connector 的人工复核回复草稿。

不会自动通过：

- `customer_trial`：必须由客户提交真实试运行材料，运营复核后才能登记 pass。

## 安全边界

- 联调执行台是只读流程，不发送消息。
- 拉取消息和线索只进入 CRM / Workflow / 回复草稿队列。
- 回复草稿仍需人工审核，不会自动外发。
- 文档和审计只保存脱敏摘要，不写入密码、token、cookie、验证码、签名密钥或 API secret。
- 交付包生成时不会主动拉取客户平台，只生成当前联调状态报告。

## 当前状态

系统能力已完成，但真实最终验收仍取决于客户平台配置与材料：

1. 客户需要完成官方 OAuth 授权。
2. 客户需要完成 callback。
3. 客户需要配置只读消息 endpoint 并产生可拉取样本。
4. 客户需要配置只读线索 endpoint 并产生可拉取样本。
5. 系统需要基于真实消息生成回复草稿。
6. 客户需要提交试运行材料并由运营审核通过。

在上述条件满足前，最终签署门禁仍应保持 blocked。
