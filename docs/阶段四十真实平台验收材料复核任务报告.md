# 阶段四十：真实平台验收材料复核任务报告

## 阶段目标

Stage39 已经能把真实平台验收材料通知给客户平台负责人，并记录回执。本阶段补齐“材料提交后谁来审核”的运营闭环：把 `submitted` 或 `needs_help` 回执同步为 CRM 复核任务，推动运营人工审核、脱敏、登记 `pass` 证据，再复验关闭缺口。

## 本阶段新增

1. 后端新增：
   - `PlatformAcceptanceEvidenceReviewTaskSyncRequest`
   - `PlatformAcceptanceEvidenceReviewTaskItem`
   - `PlatformAcceptanceEvidenceReviewTaskSyncResult`
2. 新增接口：
   - `POST /api/v1/ops/platform-acceptance-evidence-review-sync`
3. 新增 CRM 任务来源：
   - `platform_acceptance_evidence_review`
4. 前端设置页新增“复核任务”按钮。
5. 交付包新增 `真实平台验收材料复核任务.md`。
6. 验收矩阵和最终巡检新增“真实平台验收材料复核任务”。

## 行为规则

- `submitted` 回执会生成高优先级复核任务。
- `needs_help` 回执可以同步为协助任务。
- 同一个 receipt + scenario 不重复创建打开任务。
- 复核任务不会自动登记 `pass` 证据。
- 复核任务不会关闭原始真实平台验收缺口任务。

## 安全边界

- 回执材料必须由运营人工审核、脱敏后再登记为真实平台验收证据。
- 禁止在任务、回执或 artifact 中保存密码、token、cookie、验证码、签名密钥或 API secret。
- 只有 Stage35 证据登记为 `pass` 后，Stage37 才能关闭对应缺口任务。

9. 生成交付包，确认包含 `真实平台验收材料复核任务.md`。
10. 运行最终验收巡检，确认出现 Stage40 项。
