# 阶段四十三：客户材料提交入口报告

## 目标

把真实平台验收材料的采集从“运营手工代录回执”推进到“客户平台负责人可通过签名链接自行提交脱敏材料”。

## 后端

新增能力：

1. `POST /api/v1/ops/platform-acceptance-evidence-submission-link`
   - 后台生成带签名 token 的客户提交链接。
   - 默认使用当前缺失的必需真实平台验收场景。
   - 支持指定场景、接收人、负责人、过期时间。

2. `GET /api/v1/public/platform-acceptance-evidence-submission`
   - 公开 HTML 提交页。
   - 客户无需后台账号即可提交脱敏说明和证据链接。

3. `POST /api/v1/public/platform-acceptance-evidence-submission`
   - 校验签名 token、过期时间和允许场景。
   - 调用既有回执流程生成 `PlatformAcceptanceEvidenceReceipt`。
   - 自动同步 `submitted` / `needs_help` 材料为 CRM 复核任务。

## 安全边界

- 客户提交不会直接登记 pass 证据。
- 客户提交只生成回执和复核任务。
- 审核通过、登记 pass 证据、关闭缺口仍必须由运营在后台确认。
- 提交内容继续执行密码、token、cookie、验证码、签名密钥、API secret 的拦截。

## 前端

系统设置里的平台验收区域新增：

- `客户提交链接` 按钮。
- 提交链接状态、场景数、过期时间展示。
- 打开提交页、复制链接、打开链接单。

## 验收

本地和线上验收应使用非必需 `ops_health` 场景：

1. 后台生成客户材料提交链接。
2. 打开公开提交页。
3. 提交脱敏说明和证据链接。
4. 确认生成回执。
5. 确认同步复核任务。
6. 确认 `token=bad` 等敏感内容被 400 拦截。
7. 确认最终巡检出现“客户材料提交入口”，证据包含 `submission_links=` 和 `customer_submissions=`。

## 当前边界

该阶段打通了客户提交入口，但仍不会伪造官方授权、回调、消息读取、线索读取、回复草稿、客户试运行等真实平台通过证据。
