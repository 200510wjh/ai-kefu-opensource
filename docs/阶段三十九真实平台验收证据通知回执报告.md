# 阶段三十九：真实平台验收证据通知回执报告

## 阶段目标

在 Stage38 已经生成真实平台验收证据采集清单之后，补齐责任人推进闭环：系统可以把缺失证据清单生成可复制的通知草稿，并记录客户平台负责人的回执。

## 本阶段新增

1. 后端新增：
   - `PlatformAcceptanceEvidenceNoticeRequest`
   - `PlatformAcceptanceEvidenceNotice`
   - `PlatformAcceptanceEvidenceReceiptScenario`
   - `PlatformAcceptanceEvidenceReceiptRequest`
   - `PlatformAcceptanceEvidenceReceipt`
2. 新增接口：
   - `POST /api/v1/ops/platform-acceptance-evidence-notice`
   - `POST /api/v1/ops/platform-acceptance-evidence-receipt`
3. 前端设置页新增“证据通知”按钮。
4. 通知结果支持：
   - 打开通知 artifact
   - 复制通知草稿
   - 记录回执
5. 回执支持：
   - `acknowledged`
   - `needs_help`
   - `submitted`
6. 交付包新增 `真实平台验收证据通知草稿.md`。
7. 验收矩阵和最终巡检新增“真实平台验收证据通知与回执”。

## 安全边界

- 通知草稿不会自动外发，需要运营人工确认接收人和内容。
- 回执只证明责任人回应，不等于真实平台 `pass` 证据。
- 回执不会关闭 CRM 缺口任务。
- 客户提交材料后，仍需运营审核并通过 Stage35 证据登记接口登记为 `pass`。
- 禁止在通知或回执中保存密码、token、cookie、验证码、签名密钥或 API secret。

## 验证清单

1. `python -m py_compile backend/customer_service_saas.py backend/api_v1.py backend/main.py`
2. `npm run build`
3. `npm run secret-scan`
4. TestClient 登录演示商户。
5. 调用 `/api/v1/ops/platform-acceptance-evidence-notice`。
6. 确认通知草稿包含缺失场景、责任人、到期时间和安全边界。
7. 调用 `/api/v1/ops/platform-acceptance-evidence-receipt`。
8. 确认回执 artifact 不会生成 pass 证据或关闭缺口任务。
9. 生成交付包，确认包含 `真实平台验收证据通知草稿.md`。
10. 运行最终验收巡检，确认出现 Stage39 项。
