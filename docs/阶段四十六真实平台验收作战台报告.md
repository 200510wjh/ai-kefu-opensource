# 阶段四十六：真实平台验收作战台报告

## 阶段目标

第45阶段已经能把真实平台验收缺口变成冲刺包。本阶段继续向最终验收推进：把六个必需场景的真实证据、客户提交、回执、复核任务、CRM 缺口任务和签署草稿统一成“验收日作战台”。

## 本阶段新增

- 新增后端接口：`POST /api/v1/ops/platform-acceptance-live-run`。
- 新增后端模型：`PlatformAcceptanceLiveRunRequest`、`PlatformAcceptanceLiveRunScenario`、`PlatformAcceptanceLiveRun`。
- 作战台会按场景汇总：
  - 已登记真实证据数量；
  - 是否已有 `pass` 证据；
  - 客户提交和回执数量；
  - 打开的真实验收缺口 CRM 任务；
  - 打开的材料复核任务；
  - 新生成的客户提交链接；
  - 当前下一步动作。
- 作战台会生成 `Customer Final Acceptance Sign-off Draft`，用于最终签署前的客户确认草稿。
- 前端“平台接入配置向导”新增按钮：`验收作战台`。
- 最终验收巡检和验收矩阵新增 `Platform acceptance live run board`，展示 `live_run_events=`。

## 状态规则

- `ready_for_signoff`：六个必需场景均已有脱敏 `pass` 证据，且没有失败证据。
- `reviewing`：存在客户提交或 warning/fail 证据，需要运营复核后才能登记通过。
- `collecting`：仍缺真实平台证据，需要继续让客户提交或补齐官方授权材料。
- `blocked`：存在失败证据，需要先处理平台侧阻塞问题。

## 安全边界

- 作战台不会自动登记 `pass` 证据。
- 签署草稿仅在 `ready_for_signoff` 时才适合发送给客户最终确认。
- 客户提交链接、回执和复核任务都不是通过证据。
- 不记录服务器密码、平台 token、cookie、验证码、原始签名密钥或 API secret。

## 验收口径

- 生成 artifact 后标题应包含 `Real Platform Acceptance Live Run`。
- artifact 应包含 `Customer Final Acceptance Sign-off Draft`。
- 最终巡检应出现 `live_run_events=`。
- 在真实官方授权和客户试运行证据未补齐之前，系统仍应保持 `ready_with_boundaries`，不能声明完整真实平台验收完成。
