# 阶段六十八：恢复包批量重提编排报告

## 目标

阶段六十七已经支持单条恢复包复核，但运营仍需要逐条处理。阶段六十八新增批量编排，把所有 `recovered_for_review` 恢复包统一转换为客户重提动作，并避免重复生成重提请求。

## 已完成

- 新增 `POST /api/v1/ops/platform-acceptance-manifest-recovery-resubmission`。
- 支持 `execute=false` 预览：列出会请求客户重提的恢复包，不生成链接。
- 支持 `execute=true` 执行：对候选恢复包记录 `needs_customer_resubmission` 复核，并生成客户 Manifest 链接。
- 已请求过重提的恢复包会显示 `already_requested`，避免重复创建链接。
- 新增批量编排 Markdown 报告，记录每个恢复包的状态、场景、链接和下一步。
- 前端验收工具栏新增：
  - `Recovery preview`
  - `Recovery resubmit`
- 前端新增 Recovery resubmission 结果面板，可打开或复制客户 Manifest 链接。

## 安全边界

- 批量编排不会注册 pass evidence。
- `execute=false` 只预览候选项。
- `execute=true` 只写恢复复核审计并创建客户 Manifest 重提链接。
- 重复运行不会重复请求已标记 `needs_customer_resubmission` 的恢复包。
- 客户仍需通过 Manifest 提交真实、脱敏、结构化证据；最终导入仍需 URL 预检、人工复核和 `CONFIRM_PLATFORM_EVIDENCE`。
