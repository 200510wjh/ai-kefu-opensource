```text
IP：47.100.53.133

SSH：22 / 3002
```

## 当前结论

这次不是“密码错误”。密码还没有进入验证阶段。

当前现象是：服务器能 ping 通，阿里云控制台显示实例 `Ubuntu-etha` 运行中，但公网服务处于“端口能建立连接、服务不返回内容”的状态。

已验证结果：

- `47.100.53.133:22`：连接超时。
- `47.100.53.133:3002`：TCP 能连上，但 SSH banner 一直不返回，无法进入密码/密钥认证。
- `47.100.53.133:80`：TCP 能连上，但 HTTP 不返回内容。
- `47.100.53.133:443`：TCP 能连上，但 HTTPS 不返回内容。
- `47.100.53.133:8003`：连接超时。
- `https://wjhai.cn/merchant-admin/`：连接超时。
- `https://wjhai.cn/merchant-admin/api/health`：连接超时。

阿里云控制台截图确认：

- 实例名：`Ubuntu-etha`
- 状态：运行中
- 公网 IP：`47.100.53.133`
- 私网 IP：`172.24.31.48`
- 镜像：Ubuntu 24.04
- 规格：2 vCPU / 2 GiB / 40 GiB ESSD

## 判断

最可能的问题是服务器内部卡住或服务阻塞：

- `sshd` 没有正常吐出 SSH banner。
- `nginx` 或 Web 服务进程卡住，导致 80/443 建连后无响应。
- 服务器负载、内存、磁盘 IO 或系统网络栈异常。
- 阿里云轻量控制台远程连接入口也会导致浏览器页无响应，说明控制台页面/远程连接通道目前也不稳定。

- 本地端口连通性测试。
- SSH 22 和 3002 测试。
- HTTP/HTTPS 健康检查测试。
- Chrome 登录态查看阿里云控制台。
- 阿里云实例列表确认机器运行状态。

## 建议下一步

需要在阿里云控制台执行一次实例重启。重启不是删除数据，只是让系统、SSH、nginx、后端服务重新起来。
