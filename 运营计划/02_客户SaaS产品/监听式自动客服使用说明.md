# 监听式自动客服使用说明

这是比“复制一次回复一次”更进一步的桌面 Agent。

## 当前最稳模式

```bash
npm run desktop:listen -- --once --dry-run
```

作用：
- 读取当前剪贴板聊天记录。
- 调用线上 AI 客服接口。
- 打印待回复消息和推荐回复。
- 不粘贴，不发送。

## 监听剪贴板变化

```bash
npm run desktop:listen
```

作用：
- 每 3 秒检查一次剪贴板。
- 剪贴板聊天内容变化后生成回复。
- 默认会把回复粘贴到当前输入框，但不会按 Enter。

更安全的窗口白名单：

```bash
npm run desktop:listen -- --window-allowlist 微信 --window-allowlist 企业微信
```

只有当前窗口标题匹配“微信/企业微信”才工作。

## 尝试直接读当前窗口

```bash
npm run desktop:listen -- --source uia --once --dry-run
```

注意：
- 这需要安装 Python 包 `uiautomation`。
- 不是所有聊天软件都能被 UI Automation 读到。
- 如果读不到，就要做 OCR 截图识别。

## 自动粘贴但不发送

```bash
npm run desktop:listen -- --window-allowlist 微信
```

它会把推荐回复粘贴到当前输入框，但不会按 Enter。

## 自动发送

不建议直接用于真实客户。

测试号可以这样开：

```bash
npm run desktop:listen -- --window-allowlist 微信 --auto-send --confirm-auto-send 我确认自动发送
```

脚本有保护：
- 不传确认短语会阻止发送。
- 默认 20 秒内不会连续发送。
- 可以随时关闭终端停止监听。

## 正式商用推荐

正式卖给客户不要主推桌面模拟发送。

推荐做法：
- 企业微信：接企业微信客服/客户联系 API。
- 微信客服：接微信客服官方 API。
- 抖音：接抖音开放平台/企业号/私信能力，按平台权限做。
- 桌面自动化只作为个人版/临时版，不作为企业稳定版。

## 为什么不能直接无脑自动发

自动发消息是真实对外沟通，会带来：
- 发错客户。
- 重复轰炸。
- 平台风控。
- 客诉。
- 隐私泄露。

所以第一版必须有白名单、频率限制、暂停能力和人工兜底。
